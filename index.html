Skindabase

Built for this application

You paste the products in your skincare routine and get back a morning and an evening — ordered, with the ingredient clashes named and a fix for each. Built, deployed and live in an afternoon, in the stack your ad asks for.

The interesting part isn't the API call, it's the contract around it. Claude proposes a schedule; the application validates it against a Zod schema before anything renders. Malformed response, unexpected shape, or a refusal — the app degrades with a clear message rather than rendering half an object. Nothing unvalidated reaches the user.

That's deliberately the same architecture as the Auric diffuser: model proposes, application validates, nothing acts on unchecked output. There it actuates eight oil channels in someone's home; here it draws a schedule. Same discipline, different output surface — and the hardware version is why I write the web one this way.

It's scoped narrowly on purpose: ingredient scheduling only, no diagnosis, no treatment advice, and a visible pointer to a dermatologist for anything that's actually a skin concern. A narrow job is a verifiable one.

Forma.training

Shipped · 200 users

A dynamometer for climbers with a research-backed training program attached. You pull, it measures force over time, and the app turns that curve into something you can act on this session rather than a number you write in a notebook.

The interesting constraint was where climbers actually are: at a crag, on granite, with no signal. So the app is offline-first by design — PowerSync over Supabase, so a full session syncs whenever the phone finds a network again, hours later, without the user thinking about it. I designed the UX, the software architecture, and the compression algorithm for the force data. Claude and Cursor did the firmware, the UI and the backend under my direction.

The company has since stopped operating. The app still has around 200 users and 30 daily actives on the last release, and the repo is public so you can read how it was actually put together — including CLAUDE.md and the .claude/ config that shaped how the agents worked on it.

Auric — AI scent engine

Live · shipping

Auric make a diffuser that holds eight individual oils in one unit. I built the AI layer that decides what it runs. The app asks the user how they're feeling, what they're drawn to, and whether the unit should run at all — then sends that state to Claude, which returns a blend across the eight channels. The app validates the response and actuates the hardware.

The engineering that matters here isn't the API call, it's everything around it. A language model is deciding what a physical device does in someone's home, so the response has to conform to a strict contract before anything switches on: valid channels, valid proportions, nothing outside the envelope. I designed the prompt structure, the reply format, and the failure path — what the unit does when the model returns something malformed or refuses. The device degrades gracefully instead of doing nothing, or worse, something wrong.

Another developer built the app. I was brought in for the AI integration, and separately consulted on mass manufacture, DFM, DFA and electronics compliance. It's live and shipping. Under NDA, so there's no link — happy to walk through the architecture in person.

UAMTEC — Atlas & Barreleye

Lead engineer · in market

Atlas is an autonomous underwater vehicle that maps subsea and submerged environments using AI, sonar imaging and 4K capture. Barreleye Dive is the subsea camera and lighting system that goes with it. Both are commercial products you can go and read the spec sheets for right now — which is rarer, in my experience, than a repo full of prototypes.

I led the build on both with a team of eight: the electronics, the pressure-rated mechanical design, sensor fusion across DVL, IMU, depth and sonar, the tether and telemetry, and the data pipeline that turns raw sensor output into a map an operator can actually use. Concept to working system took about three months each. The rest of the two years went into manufacturing setup — which is what a pressure-rated subsea product costs before you can sell one. All five of my patents came out of this work.

Section 03

How I actually use AI

You wrote that using Claude twice doesn't make someone an AI engineer. Agreed — so here's the specific division of labour, not a logo wall.

ToolWhat I reach for it to do
Claude Architecture and the gnarly work. I keep a CLAUDE.md in the repo to enforce the project's rules — conventions, boundaries, the things I don't want quietly re-litigated at 2am by an agent that's forgotten why a decision was made. On Forma it wrote firmware, UI and backend against my architecture, and produced the bug audit and dependency analysis docs that are still in the repo.
Cursor / Windsurf The implementation grind. Multi-file refactors, wiring new screens through to the data layer, the long tail of work that's clear in my head and tedious in my hands.
v0 / Lovable / Bolt First-pass UI when I need something on screen in twenty minutes to find out if a layout is wrong. I throw the output away and keep the inspiration — it's a sketching tool, not a foundation.
ChatGPT Thinking out loud early, and unfamiliar-domain reconnaissance before I commit to an approach.
What I don't do Ship what an agent hands me without reading it. Twelve years of hardware taught me that a mistake you can't hotfix costs a tooling run — so I still review architecture, data models and anything touching a user's data line by line. Speed comes from knowing which parts deserve that.

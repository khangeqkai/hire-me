Rec. 01

Forma.training

Shipped · 200 users

A dynamometer for climbers with a research-backed training program attached. You pull, it measures force over time, and the app turns that curve into something you can act on this session. The trace at the top of this page came off it.

Climbers train at a crag with no signal, so the app is offline-first — PowerSync over Supabase, a full session syncing hours later without the user thinking about it. I designed the UX, the architecture, and the force-data compression; Claude and Cursor wrote firmware, UI and backend under my direction.

The company has stopped operating. The app still has ~200 users and 30 daily actives, and the repo is public — including the CLAUDE.md and .claude/ config that shaped how the agents worked on it.

Rec. 02

Skindabase

Live

You paste the products in your skincare routine and get back a morning and an evening — ordered, with the ingredient clashes named and a fix for each. Idea to a live URL in one afternoon.

The interesting part isn't the API call, it's the contract around it. Claude proposes a schedule; the app validates it against a Zod schema before anything renders — and the JSON Schema sent to the model is generated from that same Zod schema, so ask and accept can't drift apart. Malformed, unexpected or refused, it degrades with a clear message rather than half an object.

Same architecture as the Auric diffuser: model proposes, application validates, nothing acts on unchecked output. There it actuates eight oil channels in someone's home; here it draws a schedule. And it's scoped narrowly on purpose — ingredient timing only, no diagnosis. A narrow job is a verifiable one.

Rec. 03

Auric — AI scent engine

Shipping · advising, ongoing

Auric make a diffuser that holds eight individual oils in one unit. I built the AI layer that decides what it runs: the app asks how the user is feeling, sends that state to Claude, and gets back a blend across the eight channels — then validates it and actuates the hardware.

A language model is deciding what a physical device does in someone's home, so the response has to clear a strict contract before anything switches on: valid channels, valid proportions, nothing outside the envelope. I designed the prompt structure, the reply format, and the failure path — the unit degrades gracefully rather than doing something wrong.

Another developer built the app; I was brought in for the AI integration, and separately consulted on mass manufacture, DFM, DFA and compliance. I'm still with them in an advisory role — it's live work, not a finished engagement. My work is under NDA, so there's no code to show, but I'll walk through the architecture in person.

Sec. 04

How I actually use AI

Using Claude twice doesn't make someone an AI engineer. So here's the specific division of labour, not a logo wall.

ToolWhat I reach for it to do
Claude Architecture and the gnarly work. I keep a CLAUDE.md in the repo to enforce the project's rules — conventions, boundaries, the things I don't want quietly re-litigated at 2am by an agent that's forgotten why a decision was made. On Forma it wrote firmware, UI and backend against my architecture, and produced the bug audit and dependency analysis docs that are still in the repo.
Cursor / Windsurf The implementation grind. Multi-file refactors, wiring new screens through to the data layer, the long tail of work that's clear in my head and tedious in my hands.
v0 / Lovable / Bolt First-pass UI when I need something on screen in twenty minutes to find out if a layout is wrong. I throw the output away and keep the inspiration — it's a sketching tool, not a foundation.
ChatGPT Thinking out loud early, and unfamiliar-domain reconnaissance before I commit to an approach.
What I don't do Ship what an agent hands me without reading it. Twelve years of hardware taught me that a mistake you can't hotfix costs a tooling run — so I still review architecture, data models and anything touching a user's data line by line. Speed comes from knowing which parts deserve that.
